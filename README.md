# fgc-scouting

FIRST Global Challenge 2026（Incheon）に出る Team Japan が、次の試合の作戦を
立てるためのスカウティングアプリ。

このリポジトリは大会で実際に使ったコードの公開版。**ピット記録・写真・
本番のパスワードとアカウント情報は含まない。**自分で動かすときは
[apps/api/README.md](apps/api/README.md) の手順でパスワードを作り、
`apps/api/wrangler.jsonc` の `database_id` を自分の D1 のものに置き換える。

規約の正本は [AGENTS.md](AGENTS.md)、仕様の正本は
[要件定義書.md](要件定義書.md)、視覚の正本は
[prototype/fgc-scout/](prototype/fgc-scout/) にある。

## 常駐しない工程を置かない理由

規約の出発点は `pipeline/`（誰からもアクセスされない工程）を例示しているが、
このプロジェクトには重い算出も学習も地理データ処理も無い。
推定は数百件のスコアに対する最小二乗で、ブラウザ内で完結する。
置き場を先に作ると、中身の無いディレクトリが残る（→ [ADR 0002](docs/adr/0002-package-layout.md)）。

## 言語をまたぐ契約を置かない理由

実装言語が TypeScript だけで、言語をまたぐ境界が無い。API の型は
`hono/client` がサーバのルート定義から直接導出するので、中間表現を置く先が
無い（→ [ADR 0002](docs/adr/0002-package-layout.md)）。

## データの実体を置かない理由

可変状態は D1 に、公式データの生 JSON も D1（第2段以降は R2）に置く。
リポジトリにデータの実体を持たないので、`data/` を作らない。
