# apps/api

利用者からのアクセスを受けるサーバ。認証、権限の強制、可変状態の記録、
公式サイトの代理取得を担う。

## 役割ごとの依存

役割ごとに1つだけ選ぶ。**この表に無い役割の依存を足さない。**
依存を足すコミットで、この表に行を足す。

| 役割              | 選ぶもの                                               |
| ----------------- | ------------------------------------------------------ |
| HTTP ルーティング | Hono                                                   |
| データベース      | D1 バインディング＋SQL 直書き（ORM を持たない）        |
| 署名・鍵導出      | Web Crypto（依存を足さない。検証は `session.test.ts`） |
| 実行基盤の CLI    | wrangler                                               |

### 未決定

なし。決着した項目はこの節から消す。

## ディレクトリ

| パス              | 役割                                                      |
| ----------------- | --------------------------------------------------------- |
| `src/index.ts`    | 入口。アプリの組み立てと、公開する全ルートの宣言          |
| `src/access.ts`   | 許可表（メソッド・パス・必要権限）。純関数                |
| `src/session.ts`  | 共有パスワードの検証と署名付き Cookie。純関数＋Web Crypto |
| `src/json.ts`     | `unknown` を型述語で絞る葉モジュール                      |
| `src/official.ts` | 公式サイトの代理取得と、応答の形の吸収                    |
| `src/store.ts`    | D1 アクセス                                               |
| `migrations/`     | スキーマ変更の連番                                        |
| `scripts/`        | ビルドに乗らない道具。Node で動く                         |

## 置かないもの

| もの                                   | 正しい置き場                                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 推定の計算（得点式・回帰）             | `apps/web`（→ [ADR 0004](../../docs/adr/0004-contribution-estimation.md)）                      |
| 画面と表示の文言                       | `apps/web`                                                                                      |
| 公式データの解釈（`details` の読み方） | 読み出し側。取り込み層は原文を保つ（→ [ADR 0003](../../docs/adr/0003-official-data-ingest.md)） |
| 実行時の秘密の実値                     | 環境変数。テンプレートだけを `.dev.vars.example` に置く                                         |

## 最も破られやすい境界

規約が「最も破られやすい境界」と書いている箇所を、逐語で写す。

> **推定値を実測値として表示しない。** 数字の隣に出典（公式 / 推定 / 申告）を
> 必ず添える。

この境界はサーバ側にも及ぶ。`stale` フラグと `fetchedAt` を落とすと、
画面が「いつの数字か」を出せなくなる。

## 手順

境界の記述と混ぜないため、実行手順はこの節にまとめる。

### 秘密を用意する

```sh
cp .dev.vars.example .dev.vars
pnpm -C apps/api run hash-password -- "生徒に配る共有パスワード"
pnpm -C apps/api run hash-password -- "コーチ用の管理者パスワード"
```

出力を `.dev.vars` の `VIEWER_PASSWORD_HASH` と `ADMIN_PASSWORD_HASH` に貼る。
`SESSION_SECRET` は32バイト以上のランダム文字列にする。
`.dev.vars` は追跡しない。

### ローカルのデータベースを作る

```sh
pnpm -C apps/api run db:local
```

### 開発サーバを起動する

```sh
pnpm -C apps/api run dev
```

画面側は別のターミナルで `pnpm run dev` を起動する。開発サーバが `/api` を
このサーバへ同一オリジンでプロキシする。

### 実行基盤の型を作り直す

`wrangler.jsonc` を変えたら実行する。生成物は手で編集しない。

```sh
pnpm -C apps/api run cf-typegen
```

### 本番のデータベースを作る

まだ実行していない。実行したら `wrangler.jsonc` の `database_id` を
出力の値で置き換える。

```sh
pnpm -C apps/api exec wrangler d1 create fgc-scout
```
