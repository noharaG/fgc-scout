# 0001. 実行基盤に Cloudflare を採り、当面はカスタムドメインを持たない

- ステータス: 採用
- 日付: 2026-09-10
- 関連: [0002](0002-package-layout.md)（この基盤の上でパッケージを2つに割る）
- 関連: [0003](0003-official-data-ingest.md)（代理取得がこの基盤を要求した）

## 背景

要件を1件ずつ並べて対応表を作った（`要件定義書.md` の6章）。
出てきたのは静的資産の配信、共有パスワードの検証、複数人が並行して書く
入力の記録、公式サイトの代理取得、機体写真の保管、圏外での閲覧の6系統である。

このうち代理取得については、`https://results.first.global/` が
CORS ヘッダを返さないことを実測で確認した。
`Access-Control-Allow-Origin` が無いため、ブラウザから直接は取得できない。
同時に `Cache-Control: s-maxage=10` も確認しており、元データ自体が
10秒粒度でしか更新されない。

## 決定

Cloudflare を実行基盤とし、Workers・D1・R2 を1つのアカウントで使う。
第1段は Workers と D1 だけで動かし、機体写真を扱う第2段で R2 を足す。

カスタムドメインを持たないため、当面は `workers.dev` で配信する。

## 理由

対応表10件のうち9件が、この基盤のプリミティブと1対1で対応した。
画面と API を1つの配信単位にまとめられ、オリジンを揃えられる。

R2 を第2段に回すのは、Workers と D1 が無料プランのまま使えるのに対し、
R2 は支払い情報の登録を要する場合があるためである。
第1段（公式データの取り込みとブリーフィング）は本番に必須なので、
そこが支払い設定で止まらない構成にした。

## 検討

| 選択肢                               | 却下の理由                                                                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 静的配信だけでバックエンドを持たない | 共有パスワードの認可、複数人の並行書き込み、CORS が無い外部サイトの代理取得が、いずれも要件として実在する                                   |
| BaaS で API を書かずに済ませる       | 代理取得・生 JSON の解釈・得点式による集約を結局サーバ側に書くことになる                                                                    |
| 定期実行（Cron）で順位を取り込む     | 画面を開いた時のオンデマンド取得と、最後に成功した内容の保持で足りる。部品を1つ減らせるうえ、誰も見ていない時間に相手のサーバを叩かずに済む |
| ドメインを取得してから始める         | 大会まで数週間しかない。共有パスワードの内側に置くので、`workers.dev` のままでも実害が小さい                                                |

## 影響

`workers.dev` を使うため A-21 / A-22 から外れる。
`要件定義書.md` の9章の例外表に、解消条件つきで登録した。
ドメインを取得した時点でカスタムドメインへ移し、`workers_dev` を無効にする。

R2 を第2段に置いた結果、第1段では機体写真を保存できない。
ピット記録の写真は第2段の到達を待つ。
