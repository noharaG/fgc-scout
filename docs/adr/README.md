# docs/adr

設計判断の記録。1件1ファイルで積み、決まったことを上書きしない。

後から判明したことは本文を書き換えず、`## 追記（YYYY-MM-DD）` または
`## 訂正（YYYY-MM-DD）` として後ろへ足す。決定当時の判断と後から分かった
ことを混ぜると、当時の情報で妥当だった判断が「間違い」に見える。

## 命名規則

ファイル名は `NNNN-短い英語の要約.md`。番号は4桁連番で欠番を作らない。
`# NNNN. タイトル` のタイトルは日本語で、判断内容そのものを述べる文にする
（「〜を採用する」「〜しない」「〜で済ませる」）。分類名のタイトルは一覧を
読んでも何が決まったか分からない。

デザインと文言の判断は ADR に置かない。
ADR に置くのは構造の判断（境界・責務・依存・実行基盤・道具）だけにする。

## 番号予約表

書き始める前にここへ自分の番号を追記する。ディレクトリの一覧だけで番号を
決めない。未追跡のファイルは他ブランチにも履歴にも現れないため、
ディレクトリを見るだけでは空き番号を判定できない。

```bash
git status --porcelain --untracked-files=all -- docs/adr
git ls-tree -r --name-only origin/main -- docs/adr
```

| 番号       | 内容             | 状態 |
| ---------- | ---------------- | ---- |
| 0001〜0004 | 上の一覧のとおり | 確定 |
| 0005       | 未予約           | —    |

```markdown
- ステータス: 提案 / 採用 / 却下 / 置き換え済み (→ NNNN)
- 日付: YYYY-MM-DD
- 関連: [NNNN](NNNN-short-summary.md)（なぜ関連するか）

## 背景

## 決定

## 理由

## 検討

（採らなかった案を1案ずつ、却下の理由と対にして書く）

```
