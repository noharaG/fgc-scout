# 0002. パッケージを apps/api と apps/web の2つだけにする

- ステータス: 採用
- 日付: 2026-09-10
- 関連: [0001](0001-cloudflare-and-origin.md)（この基盤を前提にしている）

## 背景

規約 S-01 はトップレベルを「誰がアクセスするか」で切ることを定めている。
規約の出発点（09章）は `apps/api` `apps/web` `pipeline` `contracts` `data` の
5つを例示しているが、これは元プロジェクトの要件から出た形である。

このプロジェクトの要件を数えると、重い算出も学習も地理データ処理も無い。
言語をまたぐ境界も無く、実装言語は TypeScript だけである。

## 決定

ワークスペースのメンバーを `apps/api` と `apps/web` の2つだけにする。
`pipeline/` `contracts/` `data/` `packages/` は作らない。

推定の計算は `apps/web` の中に置き、独立したパッケージにしない。

## 理由

`pipeline/` は「誰からもアクセスされない工程」の置き場だが、
このプロジェクトにその工程が無い。推定は数百件のスコアに対する
最小二乗であり、ブラウザ内で完結する（→ [0004](0004-contribution-estimation.md)）。

`contracts/` は言語をまたぐ契約の置き場だが、言語が1つしかない。
API の型は `hono/client` がサーバのルート定義から直接導出するので、
中間表現を置く先が無い。

`data/` はデータの実体の置き場だが、可変状態は D1 に、
公式データの生 JSON は D1（第2段以降は R2）に置く。
リポジトリにデータの実体を持たない。

消費者が1つしかないものをパッケージに切り出しても境界の強制は増えず、
置き場だけが2つのツリーに散る（S-10）。

## 検討

| 選択肢                                        | 却下の理由                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------ |
| 推定の計算を `packages/scoring` に切り出す    | 消費者が `apps/web` の1つしかない。2つ目の消費者が現れた時点で切り出す         |
| 得点式を `contracts/` に置いて API と共有する | API は得点式を読まない。推定は画面側だけが行う                                 |
| 空の `pipeline/` を先に作っておく             | 中身の無い置き場をワークスペースに登録しない（S-11）。必要になった時点で起こす |

## 影響

`vite.config.ts` の `defaultPackage` は `./apps/web` を指す。

推定のコードは `apps/web/src` の中に置く。ここが2つ目の消費者を持った時点で
（たとえば API 側でも予測を計算する必要が出た時点で）、
この ADR を置き換えてパッケージへ切り出す。
